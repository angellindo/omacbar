## Verified upstream patterns

[Vercel doctor](https://vercel.com/docs/cli/doctor) checks CLI version/install/PATH duplicates, login/team/project, `vercel.json`, and service status. It never prompts, logs in or links projects. Reports OK/Warning/Failed/Skipped, explains skipped prerequisites, supplies exact next commands, and JSON includes `id`, `status`, `message`, `next` plus counted `summary`. **It exits 0 after completed checks even when checks fail**; consumers must inspect results. Borrow structured actionable reporting, not its network/auth checks.

[Homebrew doctor documentation](https://docs.brew.sh/Manpage#doctor-dr---list-checks---audit-debug-diagnostic_check-) instead specifies nonzero for potential problems and allows named checks/`--list-checks`. [Implementation at 95d4938386e5b1536b3b961baa9d0267abd57047](https://github.com/Homebrew/brew/blob/95d4938386e5b1536b3b961baa9d0267abd57047/Library/Homebrew/cmd/doctor.rb) enumerates diagnostic methods, runs slow checks last, excludes irrelevant cask checks, and marks the process failed on findings. Its hidden JSON switch emits tier/findings. Therefore exit policy is a project decision, not a universal doctor convention.

## Adopted project decisions

Use bootstrap `build` profile and explicit `runtime` profile. Stable IDs, schema_version, four lowercase statuses, evidence/next arrays and summary counts. `ok` means the stated check ran successfully; `warning` covers optional degradation/unavailable probes; `skipped` states unmet prerequisites or irrelevant scope; `failed` means demonstrated failure. Exit 0 for no required blockers, 1 for required failure **or required unverified/skipped capability**, 2 for usage/internal failure. State scope prominently; prebuild success cannot promise runtime readiness.

Keep subprocesses allowlisted, argv-only, time/output bounded and offline. PATH/version/package presence prove availability only. Optional `timeout 5s vulkaninfo --summary` and `timeout 5s wayland-info` establish stronger facts when installed, not Rune render/window success; missing probes cannot go green. Do not invoke them in default metadata-only checks. Device permission metadata is optional, never Fn/physical-panel verification; see `docs/research/0002-input-fn-modifiers.md` and `0003-rune-fit.md`.

The native `touchbar-doctor-probe` shares `tb-config::ConfigFile::reload_resolved`, hence `tb-core::config::{parse,validate}` and existing theme resolution; Python does not duplicate the domain. `ConfigFile::load/load_resolved` can create defaults; `reload_resolved` reads without creation. Missing config is first-run information, unavailable validator means unverified. Return sanitized issue categories, not config commands/values.

The initial handoff supports Codex only: supplied local help confirms `codex [OPTIONS] [PROMPT]`, `-C/--cd`. Resolve installed executable, pass prompt as one argv with repo cwd, preserve approvals; explicit absence errors with no install/fallback. Add inspect-only mode, private artifacts (0700 directory/0600 files), bounded sanitized doctor/repo facts and repo-owned playbook. Doctor blockers must not prevent assistance. Direct agent to read evidence as data, repair within authorization, rerun checks and report manual steps; no automatic posting or remote playbook replacement. Claude support remains unverified and unnecessary for the minimal scope.

## Implementation bounds

The bootstrap uses installed concrete rustup toolchain executables and bounded argv-only capture. Ordinary checks have 5-second/16-KiB bounds; native GPU has 20 seconds and native output 64 KiB. Triage bounds the whole doctor aggregation at 110 seconds/64 KiB, while its explicitly launched interactive Codex retains inherited stdio and normal approvals. Context and prompt files are local/private (0700 session/0600 files), created through no-follow directory handles. No native input probe opens events or uinput. Runtime window readiness is local Unix socket reachability only. The human checklist records unverified GUI/physical behavior.
